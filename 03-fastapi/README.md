# FastAPI

## Objective

Build a FastAPI endpoint with strict schema validation and document
the automated error serialization flow for malformed requests.

## Implementation

The FastAPI application contains:

- Root endpoint: `/`
- Health endpoint: `/health`
- Data endpoint: `/items`
- Query parameter filtering using `min_id`
- Pydantic schema validation
- Automatic validation error responses
- Automatic OpenAPI/Swagger documentation

## Schema Validation Rules

### Query Parameter: `min_id`

- Type: Integer
- Default: `1`
- Constraint: Must be greater than `0`

Example of valid request:

`/items?min_id=2`

Example of invalid request:

`/items?min_id=0`

The invalid request returns HTTP `422 Unprocessable Entity` with
structured validation details.

### Item Schema

The `Item` Pydantic model defines:

- `id`: Integer greater than `0`
- `name`: String between `2` and `50` characters

## Automated Error Serialization

FastAPI validates request parameters using Pydantic.

When invalid data is received, FastAPI automatically generates a
structured JSON error response containing the validation type,
location, message, received input, and validation context.

## API Documentation

Interactive Swagger UI is automatically generated by FastAPI and is
available at:

`/docs`
